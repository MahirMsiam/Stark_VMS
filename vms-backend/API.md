# VMS Vehicle API

Base URL (local): `http://localhost:9001`
All bodies are JSON (`Content-Type: application/json`). All vehicle endpoints require a bearer token (see Authentication).

## Authentication

Every `/api/vehicles` call needs a token from the login endpoint:
`Authorization: Bearer <accessToken>`. Only `POST /api/auth/login` and `GET /actuator/health` are public.

### `POST /api/auth/login`
Request:
```json
{ "email": "admin@starkgroup.com", "password": "••••••••" }
```
`200` response:
```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiJ9…",
  "tokenType": "Bearer",
  "expiresAt": "2026-11-23T01:18:44.202Z",
  "email": "admin@starkgroup.com"
}
```
- Email is case-insensitive and trimmed.
- The token is a signed JWT (HS256), valid for 8 hours by default (`JWT_TTL`). There is no refresh:
  sign in again after `expiresAt`. Signing out = the client discards the token.

| Status | When | `detail` |
|---|---|---|
| `400` | Email/password missing or email malformed | `Validation failed` + `errors` |
| `401` | Wrong email **or** wrong password (deliberately the same message) | `Invalid email or password` |

### Protected endpoints without a valid token
Missing, malformed, tampered or expired token → `401` with header `WWW-Authenticate: Bearer`:
```json
{ "status": 401, "title": "Unauthorized", "detail": "Please sign in to continue" }
```

### Accounts
Users live in the `users` table with BCrypt password hashes. The first admin is created at startup from
`ADMIN_EMAIL` / `ADMIN_PASSWORD` (`.env` or environment) — passwords are never in source code, migrations or logs.

## Vehicle object

```json
{
  "id": 3,
  "vehicleNumber": "DHAKA METRO-GA-11-2345",
  "company": "Stark Logistics",
  "type": "TRUCK",
  "brand": "Tata",
  "model": "LPT 1613",
  "status": "AVAILABLE"
}
```

| Field | Type | Rules (request) |
|---|---|---|
| `id` | number | Response only. Generated by the server. |
| `vehicleNumber` | string | Required, 4–30 characters, letters/numbers/spaces/hyphens. **Unique.** Stored trimmed, upper case, single spaces (`" ka-01  ab "` → `"KA-01 AB"`). |
| `company` | string | Required, max 100 characters. |
| `type` | enum | Required. `CAR`, `SUV`, `VAN`, `MICROBUS`, `BUS`, `TRUCK`, `PICKUP`, `MOTORCYCLE` |
| `brand` | string | Required, max 40 characters. |
| `model` | string | Required, max 40 characters. |
| `status` | enum | Required. `AVAILABLE`, `IN_USE`, `MAINTENANCE`, `INACTIVE` |

Request bodies (create and update) contain every field except `id`.

## Endpoints

| Method | Path | Success | Errors |
|---|---|---|---|
| `GET` | `/api/vehicles` | `200` array of vehicles, oldest first | `401` |
| `GET` | `/api/vehicles/{id}` | `200` vehicle | `404`, `400` (non-numeric id) |
| `POST` | `/api/vehicles` | `201` created vehicle + `Location: /api/vehicles/{id}` header | `400`, `409` |
| `PUT` | `/api/vehicles/{id}` | `200` updated vehicle | `400`, `404`, `409` |
| `DELETE` | `/api/vehicles/{id}` | `204` no body | `404` |
| `GET` | `/actuator/health` | `200` `{"status":"UP","components":{"db":{"status":"UP"},…}}` | `503` when the database is down |

`PUT` replaces all fields (send the full object). A vehicle may keep its own number on update.

## Errors

Every error uses the same JSON shape (RFC 9457 ProblemDetail):

```json
{ "status": 409, "title": "Conflict", "detail": "Vehicle number KA-01 is already registered" }
```

Validation failures add `errors`: one message per field, ready to show next to form inputs.

```json
{
  "status": 400, "title": "Bad Request", "detail": "Validation failed",
  "errors": {
    "vehicleNumber": "Vehicle number must be 4-30 characters",
    "company": "Company is required",
    "type": "Type is required"
  }
}
```

| Status | When | `detail` example |
|---|---|---|
| `400` | A field is missing or invalid | `Validation failed` + `errors` |
| `400` | Unknown `type`/`status` value | `Validation failed` + `errors: {"type": "Must be one of: CAR, SUV, …"}` |
| `400` | Body is not valid JSON | `Request body is not valid JSON` |
| `404` | No vehicle with that id | `Vehicle 42 not found` |
| `409` | `vehicleNumber` already used by another vehicle (case and extra spaces ignored) | `Vehicle number KA-01 is already registered` |

## Try it with curl

```bash
# Sign in and keep the token (bash)
TOKEN=$(curl -s -X POST http://localhost:9001/api/auth/login -H "Content-Type: application/json"   -d '{"email":"admin@starkgroup.com","password":"<your password>"}' | sed -E 's/.*"accessToken":"([^"]+)".*//')
AUTH="Authorization: Bearer $TOKEN"

# Create
curl -i -H "$AUTH" -X POST http://localhost:9001/api/vehicles -H "Content-Type: application/json" \
  -d '{"vehicleNumber":"DHAKA METRO-GA-11-2345","company":"Stark Logistics","type":"TRUCK","brand":"Tata","model":"LPT 1613","status":"AVAILABLE"}'

# List / read one
curl -H "$AUTH" http://localhost:9001/api/vehicles
curl -H "$AUTH" http://localhost:9001/api/vehicles/1

# Update (full object)
curl -H "$AUTH" -X PUT http://localhost:9001/api/vehicles/1 -H "Content-Type: application/json" \
  -d '{"vehicleNumber":"DHAKA METRO-GA-11-2345","company":"Stark Logistics","type":"TRUCK","brand":"Tata","model":"LPT 1613","status":"IN_USE"}'

# Delete
curl -i -H "$AUTH" -X DELETE http://localhost:9001/api/vehicles/1
```

Windows PowerShell: use `curl.exe` (not the `curl` alias) or `Invoke-RestMethod`.

## CORS
Browsers may call `/api/**` only from allowed origins: any `http://localhost` / `http://127.0.0.1` port by default.
Set `CORS_ALLOWED_ORIGINS` (comma-separated) for production, e.g. the deployed Flutter URL.

## Not yet included

- Login rate limiting (brute-force protection).
- Paging/sorting/search on the list endpoint.
